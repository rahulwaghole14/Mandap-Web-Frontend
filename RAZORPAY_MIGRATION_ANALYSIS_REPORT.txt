RAZORPAY MIGRATION ANALYSIS REPORT
==================================================

1. Executive Summary
==================================================
This report details the end-to-end Razorpay payment integration comparison between the React project (Project A) and the HTML project (Project B). 

The HTML project has successfully and accurately mirrored the Public Event Registration payment workflow (including complex retry logic, polling fallbacks, and deduplication guards). However, it entirely lacks the Admin Manual Registration payment flow. The overall Razorpay integration is approximately 50% complete across the entire system.

2. React Razorpay Architecture (Source of Truth)
==================================================
The React implementation handles Razorpay in two distinct areas:

1. Public Registration (`src/pages/EventRegistrationPage.jsx`)
2. Admin Manual Registration (`src/components/ManualRegistrationModal.jsx`)

Core API Service (`src/services/eventApi.js`):
- `initiatePublicRegistration` (Public)
- `confirmPublicPayment` (Public - includes 5-attempt exponential backoff)
- `checkPublicRegistrationStatus` (Public - used for polling fallback)
- `initiatePayment` (Admin/Auth)
- `confirmPayment` (Admin/Auth)

3. HTML Razorpay Architecture
==================================================
The HTML implementation relies on:
- `event-registration.html` (Injects Razorpay SDK)
- `js/pages/event-registration.js` (Handles Public Registration)
- `js/utils/api.js` (Handles API calls)

Currently, only the Public Registration flow exists in HTML. The Admin Manual Registration flow is entirely missing.

6. Security Analysis
==================================================
✓ Order Generation: Both projects correctly rely on the backend to generate `razorpay_order_id`, keeping the secret key safe.
✓ Signature Verification: Handled securely on the backend in both flows.
✓ Duplicate Payment Prevention: Both frontends implement strict boolean guards (`isPaymentConfirming`) to ignore duplicate Razorpay callbacks.
✓ Replay Protection: Handled correctly via backend signature verification.
✗ Admin Authorization: HTML is missing the authenticated payment endpoints, leaving admins unable to process manual online payments securely.

12. Risks
==================================================
- The primary risk is the total absence of the Admin Manual Registration payment flow. If an admin needs to register a user manually and collect payment via Razorpay, they currently cannot do so in the HTML project.
- Polling logic relies heavily on backend webhooks completing within 12 seconds. If the webhook is delayed, the user will see a failure message even if they paid. (This risk exists equally in React).

14. Production Readiness

The Admin Portal is NOT production-ready, as manual registrations via Razorpay are entirely unsupported.
